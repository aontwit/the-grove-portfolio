### 4.1 หน้าแรก Perf 68 (TBT 2,130 ms)

ตัวถ่วงคือการบูต WebGL ของ diorama บน hero ซึ่ง **เป็นการตัดสินใจเชิงผลิตภัณฑ์ที่ prompt ของ Stage 6 กำหนดไว้**
("hero = FloorPlanScene เต็ม viewport") การแก้ให้คะแนนขึ้นต้องเปลี่ยนพฤติกรรม เช่น

- ไม่โหลดโมเดลจนกว่าผู้ใช้จะกดดู (หน้าแรกเหลือแค่แปลนย่อ) — เปลี่ยนคอนเซปต์ §0 ที่ให้โมเดลเป็นพระเอก
- ลดจำนวน mesh ของ diorama ลง (ตอนวัด 265 draw calls / 67k triangles จากเฟอร์นิเจอร์ใบบัว 36 ชิ้น
  — ร่มไม้ 56 ชิ้น และลมเย็น 60 ชิ้นเพิ่มเข้ามาทีหลัง ยังไม่ได้วัดผลต่อหน้าแบบบ้าน)

ทั้งสองทางเป็นการตัดสินใจของเจ้าของโปรเจกต์ ไม่ใช่การเก็บงาน QA

### 4.2 ~~contrast ของ chip สถานะ — ขัดกันเองใน DESIGN-SPEC §1~~ — แก้แล้ว

ตอนนี้ chip ใช้ตัวอักษร `marigold-deep` (จอง 5.24:1) และ `st-sold` `#4F4C46` (ขายแล้ว 7.12:1) — ดู `src/lib/status.ts`
ข้างล่างคือบันทึกของรอบ 2026-10-01

| คู่สี | ratio | เกณฑ์ §1 |
|---|---|---|
| ขายแล้ว `#6E6A63` บน `#ECEAE6` | **4.48:1** | ≥4.5:1 |
| จอง `#C28214` บนพื้นขาว | **3.23:1** | ≥4.5:1 |
| ว่าง `#2E6B4E` บน `#E5EFE9` | 5.36:1 | ผ่าน |

§1 ระบุคู่สีเหล่านี้ไว้ในตาราง **และ**ระบุว่าทุกข้อความต้อง ≥4.5:1 — สองข้อนี้ขัดกันเอง
`DESIGN-SPEC.md` เป็น IMMUTABLE ผมจึงไม่แก้ ทางเลือกที่ยังอยู่ในกรอบ §1 (ต้องให้เจ้าของเลือก):

1. ใช้ `ironwood` เป็นสีตัวอักษรบน chip แล้วให้สีสถานะอยู่ที่พื้นกับเส้นขอบแทน (ผ่านทั้งสองเกณฑ์ ไม่ต้องเพิ่มสีใหม่)
2. ปรับ `#6E6A63` และ `#C28214` ให้เข้มขึ้นใน spec
3. ปล่อยไว้แล้วรับว่า chip ไม่ผ่าน WCAG AA

### 4.3 `label-content-name-mismatch` บนแปลน 2D และผังโครงการ

axe เทียบ "ข้อความที่มองเห็น" กับ "ชื่อที่ screen reader อ่าน" แบบ string containment
ชื่อมาจาก `aria-labelledby` ที่ชี้ไปยัง `<text>` ของจริง → อ่านได้ว่า "นั่งเล่น 27.50 ตร.ม."
แต่ข้อความใน SVG ต่อกันโดยไม่มีช่องว่าง → "นั่งเล่น27.50 ตร.ม." axe จึงถือว่าไม่ตรง

เป็น false positive จากวิธีต่อข้อความของ SVG ไม่ใช่ปัญหาการใช้งานจริง (ผู้ใช้ screen reader ได้ยินข้อมูลครบ)
การแก้ต้องยุบ `<text>` สองชิ้นเป็นชิ้นเดียวที่มี `<tspan>` ซึ่งทำให้โครงสร้างแย่ลงเพื่อให้ผ่าน rule — ไม่คุ้ม

### 4.4 CLS 0.255 บน `/register`

เหลือจากการสลับฟอนต์ (`display: "swap"` ของ Bai Jamjuree/Anuphan) ซึ่งทำให้ข้อความขยับตอนฟอนต์จริงมาถึง
แก้ได้ด้วย `display: "optional"` แต่แลกกับการที่ฟอนต์อาจไม่ขึ้นเลยบนเน็ตช้า ซึ่งขัด §2 ที่บังคับฟอนต์สองตัวนี้
